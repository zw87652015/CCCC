# 定时暂停与配置导入／导出

日期：2026-10-24

状态：需求范围已确认，本文待用户审阅。

## 基线与范围

以原作者 `upstream/main` 的 v1.6（`53d64958a07b231b0f15a141bb450692b87e5e0a`）为开发基线。
本地分支为 `feature/timed-pause-config-backup`。旧 `main` 分支及本地可执行文件已保留，
不将旧显示配置实现合并到新基线。GitHub Fork 保留用于后续贡献，本文不授权自动创建新 PR。

本次只增加定时暂停、配置导入／导出，Windows 与 macOS 提供相同的产品行为。
用户已选择完整备份：外观、提醒行为、声音和忽略应用；系统自启动与授权保持本机状态。

## 实现方式的选择

推荐在现有暂停状态和自定义窗口中扩展：暂停状态增加截止时间，设置增加独立 JSON 编解码模块。
这样可沿用当前托盘、配置保存和刷新逻辑，无须增加独立配置中心。

另一种方式是只导出注册表或 UserDefaults；它与平台耦合，文件也难以检查，不采用。
将两端配置改为由 JSON 文件直接驱动会改动全部持久化流程，超出本次需求，也不采用。

## 定时暂停

### 用户入口

- 托盘／菜单栏保留原有暂停开关，增加“暂停 15 分钟”“暂停 30 分钟”“暂停 1 小时”。
- 暂停时可选择“立即恢复”；再次选择时长，以当前时刻重新计时。
- 托盘提示文字区分运行、手动暂停、定时暂停，并为定时暂停显示恢复时间。
- 自定义窗口原有暂停开关继续有效；手动改变开关会取消之前的定时任务。
- 暂停影响与当前 `Paused` 一致，包括自动复制提醒、失败提醒、Caps Lock 提醒及相应声音。
- 暂停开始时关闭已显示的自动提醒并停止尚未触发的失败检测，避免旧提醒继续出现。
- 用户主动查看剪贴板和设置中的主动预览沿用现有行为，不受自动提醒暂停限制。

### 状态与计时

- 使用现有 `Paused` 和新增的 UTC 截止时间 `PauseUntilUtc`，统一管理所有暂停入口。
- 运行：`Paused=false`，截止时间为空。
- 手动暂停：`Paused=true`，截止时间为空。
- 定时暂停：`Paused=true`，截止时间有效。
- 到期恢复：清空截止时间、写入 `Paused=false`，刷新托盘和自定义窗口。
- 只在定时暂停期间启用检查计时器，每秒核对实际 UTC 截止时间，不累计计时器触发次数。
- 启动时先核对截止时间。重启后未到期则继续暂停，已到期则恢复。
- 休眠期间不消耗额外计时逻辑；唤醒后的首次检查到期即恢复。
- 截止时间损坏时按运行状态恢复并清理无效定时数据，避免变成永久暂停。
- 原有仅设置 `Paused=true` 的配置继续表示手动暂停。
- 暂停到期不读取或展示剪贴板内容，只恢复正常监听行为。

## 配置导入／导出

### 用户入口与文件

- 在“自定义 → 常规”增加“导出配置…”和“导入配置…”按钮。
- 使用系统文件选择框，UTF-8 JSON，默认文件名 `CCCC-settings-YYYY-MM-DD.json`。
- 文件头包含 `format: "cccc-settings"`、`version: 1`、`platform`，具体设置放在 `settings` 对象。
- 使用明确字段白名单，不直接序列化运行时对象或枚举整个注册表／UserDefaults。
- 第一版支持同平台完整备份和恢复。跨平台文件明确拒绝，避免 Windows exe 名与 macOS bundle ID、
  自由位置与随机位置等不同语义被错误套用；文件格式预留以后迁移的空间。

### 覆盖范围

| 类别 | 内容 |
| --- | --- |
| 外观 | 主题、配色、自定义颜色、字体、字号、卡片缩放、简易模式、透明度 |
| 提醒行为 | 失败提醒、Caps Lock 提醒、显示时长、保持到点击、位置、来源显示及详细程度 |
| Caps Lock 专属 | 独立位置、尺寸、时长、保持到点击，以及平台实际支持的位置参数 |
| 声音 | 提示音开关、自定义成功音与失败音文件路径 |
| 其他偏好 | 语言、自动检查更新、忽略应用列表 |

不包含剪贴板内容、暂停状态与截止时间、开机自启动、系统授权和授权询问状态。
不打包字体和声音文件。导入后不存在的声音文件回退到内置声音；不可用字体回退到默认字体，
并在结果提示中说明。路径仅作为资源位置，不执行导入文件中的任何程序。

### 导入流程

1. 限制输入文件大小为 1 MiB，检查 JSON、格式标识、版本与平台。
2. 将白名单字段解析到独立候选配置，验证字段类型、枚举、数值范围、颜色与列表长度。
3. 缺失字段保留当前值；可清空的颜色／声音／字体字段使用显式 `null` 表示恢复默认。
4. 未知字段忽略；错误类型、越界数值、损坏 JSON、未知版本与平台不符会拒绝整次导入。
5. 验证通过后说明将替换的设置类别，用户确认才应用。取消不会改变设置。
6. 在应用配置目录保存一份 `settings-before-import.json`，作为最近一次导入前的完整备份。
   若此备份无法写入，中止导入。
7. 更新已有设置对象／Prefs，保存并统一刷新托盘、声音、自定义窗口及卡片显示。
   保留原暂停状态和定时任务、自启动、系统授权。
8. 保存失败时回滚本次导入；报告错误。成功时提示已导入及资源回退情况。

导出采用临时文件写入后替换目标文件，避免失败后留下不完整备份。
导入前备份同样使用此方式。覆盖用户选定的既有文件沿用系统保存框的覆盖确认。

## 模块边界

- `Settings.cs`／`Settings.swift`：新增截止时间持久化，保持现有配置的读取默认值。
- 暂停控制模块：负责状态转换、截止时间检查；由 App 连接托盘、自定义窗口和计时器。
- 配置文件模块：负责白名单、版本、解析验证、导入前备份和候选配置，不接触剪贴板。
- `App.cs`／`App.swift`：连接暂停控制、菜单动作、配置刷新和提醒生命周期。
- `Customize.cs`／`Customize.swift`：增加导入／导出入口，暂停开关通过统一逻辑更新状态。
- `Strings.cs`／`Strings.swift`：补充中英文文案，沿用上游本地化方式。

## 验收与验证

- 使用可控时钟测试暂停的开始、重设、手动取消、到期、重启、休眠跨越截止时间和无效持久化。
- 验证手动暂停不会被旧定时任务自动恢复；导入配置不会取消现有暂停或恢复已暂停的提醒。
- 验证暂停后不再出现排队的失败提醒，复制和 Caps Lock 两种自动卡片均被抑制。
- 对所有白名单设置进行导出／导入往返检查，包括默认值、自定义值、可清空值和忽略应用列表。
- 拒绝格式、版本、平台、类型、范围错误与过大文件，验证失败／取消不改变配置。
- 验证导入前备份写入失败会中止、配置写入失败会回滚，成功导入可通过备份恢复。
- 验证自启动、授权、暂停和剪贴板不进入备份或被导入更改。
- 验证声音／字体缺失的回退，以及中文／英文菜单和提示。
- 在独立注册表测试路径／独立 UserDefaults 域运行测试，不修改实际用户配置。
- Windows 完成构建、核心回归检查和界面渲染检查。macOS 使用可用环境编译验证；
  若本机仍无 macOS 环境，明确报告尚未验证，不将静态检查称为编译成功。

## 设计自检

- 本文所有范围和失败行为均给出了具体规则，无待定占位符。
- 导入不恢复暂停，定时暂停独立持久化，两项功能之间的关系一致。
- 仅围绕两项功能增加控制模块与编解码模块，不重写上游显示配置或剪贴板监听。
- 平台差异通过同平台文件限制明确处理，不承诺未经实现的跨平台迁移。
